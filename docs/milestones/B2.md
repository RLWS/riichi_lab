## 批次与停止语义

`rilab/online/ranked.py` 从独立配置读取预定局数、总时长、单会话时长、匹配等待时长和五个显式阈值。连接前校验配置、写入 manifest，记录源码哈希、commit/dirty、Python/依赖、profile、训练 tag/commit、部署声明的权重哈希和实际模型元信息。HTTP API 不提供权重哈希，配置声明仍须由部署者核对；不把声明误称为远程实测哈希。

每局新建独立 policy/tracker/立直计划和 WebSocket，共用一个已预热的异步 HTTP 连接池。每局连接前和结束后检查模型元信息；任何变化均使批次失败。原局断线不恢复，不自动重试失败槽位，不读取旧目录续跑，不自动增加计划局数。

任何会话/协议故障、推理错误、动作 rejected/unparseable/stale、缺失 ack、状态/候选不兼容、模型变化、写盘失败都会阻止下一局。推理失败即使获得合法 fallback 且 fallback 配额未耗尽，也强制停止批次。fallback 和 defaulted 按整个批次累计；全部阈值在每局结束、审查及落盘后作为下一局开局门槛。

单纯阈值触发后继续服务当前局，收到 end_game 后停止，不因延迟或时间库阈值主动中途断线。匹配等待、单会话/批次总时长是硬等待上限；达到上限则关闭当前连接并保留未完成记录。总时长计入模型启动与元信息检查，连接前再次检查剩余预算；退出清理、日志写盘不强制截断。用户取消时保存当前会话及 cancelled 批次摘要，不开启下一局。

批次的 `attempted` 表示已登记的会话槽位，`games_started` 表示确实收到 start_game，`games_completed` 表示本地确实收到终局。提前断线时不将服务器之后可能自行结束的对局记为本地完成。

## 示例配置

`configs/arena_ranked.yaml` 是待执行的保守示例计划，不代表用户已指定真实排位预算。

| 配置 | 示例值 | 触发语义 |
|---|---:|---|
| max_games | 1 | 最多一个会话槽位 |
| max_total_seconds | 7,200 | 包含启动和匹配；耗尽不再连接 |
| session_timeout_seconds | 7,200 | 每会话的硬等待上限 |
| matchmaking_timeout_seconds | 300 | 等待 start_game 的绝对上限，队列通知不续期 |
| max_fallbacks | 0 | 批次累计数超过上限则停止 |
| max_defaulted | 0 | 批次累计数超过上限则停止 |
| max_server_elapsed_ms | 2,500 | 任一服务器耗时超过上限则停止 |
| min_bank_ms | 1,000 | 任一 ack 剩余时间库低于下限则停止 |
| min_deadline_margin_ms | 500 | 请求 deadline_ms 减对应 ack elapsed_ms 低于下限则停止 |

上限相等、下限相等均允许；计数、时间字段拒绝负数/无穷/布尔伪整数。缺失 ack 耗时/时间库或无法计算期限余量也会阻止下一局。ranked 固定使用 match_rounds=8，校验 profile 与训练 revision，平台 token 与 HTTP key 环境变量独立；真实 token 只通过环境传入，不写配置。

示例入站估计及发送余量各为 0.5 秒，供执行前审查，不表示已覆盖 B1 的 17.609 秒尾部抖动；该 B1 样本会同时触发示例延迟、剩余时间库和期限余量门槛。没有基于这一次样本声称已精确测出单向网络延迟。会话计时切换为 `time.perf_counter()`，继续保持单调时钟语义，并改善 Windows 上本地计时粒度。

## 日志与状态

输出到新的批次目录：

- `manifest.json`：开局前的计划与身份信息，元信息预热完成后封存模型信息。
- `summary.json`：预算、已登记/开局/完成计数、停止原因、累计 fallback/defaulted、逐局摘要与产物哈希。采用临时文件替换写入；已有目录拒绝覆盖和续跑。
- `game_0001/session.jsonl`：自家可见的完整传输事件、原始 Observation、事件增量、task/hand_id、完整 state、候选、物理动作绑定、模型输出、计划立直弃牌、发送动作、耗时与 ack 确认的执行结果。
- `game_0001/summary.json` 与 `review.json`：会话状态、终局/故障、请求回复数量、ack 审查、序列化往返、延迟及剩余预算。ranked 审查依据 end_game，不要求或伪造 validation_result。

每局保持 B0 的有界内存日志，关闭连接后通过工作线程完整写盘，再允许下一局。日志条数/字节耗尽使会话失败；写盘失败绝不继续开局。正常取消会落盘；进程被强制杀死或系统掉电仍可能丢失尚在内存中的当前局日志，不宣称提供崩溃事务恢复。

只有全部预定会话在无故障且阈值未触发时 `completed_budget` / 退出码 0。触发阈值为 `stopped`，故障为 `failed`，用户取消为 `cancelled`，均不继续开局；即使平台接受了所有动作，也不掩盖停止原因。结果仅作协议与运行稳定性记录，不产生棋力提升结论。

## 命令与验收

无 token、无服务、无输出目录、无网络连接的配置检查：

```powershell
.venv/Scripts/python.exe -m rilab.cli arena-online --mode ranked --dry-run
```

未来实际运行需先确定批次/阈值、核对实际 HTTP 部署及密钥环境，再显式调用：

```powershell
.venv/Scripts/python.exe -m rilab.cli arena-online --mode ranked --config configs/arena_ranked.yaml --output-dir outputs/ranked_new_batch
```

默认 `--mode validate` 继续使用 B1 单次验证；选择 ranked 时默认加载独立的 arena_ranked.yaml，避免复用东风验证的 match_rounds=4。

`arena-online` 的 `--output-dir` 可省略（ranked / validate 均支持）。省略时使用当前工作目录下的 `outputs/`，目录名由配置中的版本 tag（若有）、adapter_profile、match_rounds、max_games（仅 ranked）、pass_bias 和本地启动时间（精确到微秒）组成；`pass_bias: null` 记为 `pbdefault`，表示使用服务端默认值。启动时在 stderr 打印目录，最终 stdout JSON 包含 `output_dir`。显式指定路径时仍要求新目录，不覆盖已有结果；`--dry-run` 不创建目录。

例如可直接运行：

```powershell
.venv\Scripts\python.exe -m rilab.cli arena-online --mode ranked --config configs/arena_ranked_v120.yaml
.venv\Scripts\python.exe -m rilab.cli arena-online --mode ranked --config configs/arena_ranked_v130.yaml
```

v1.2.0 配置生成的路径形如 `outputs/ranked_v1.2.0_legacy_v1_2_r8_g100_pbdefault_20261104_123456_123456`。

# B0 协议模拟验收

2026-11-03：B0-1–B0-7 已实现并通过本地模拟验收。使用真实本机 WebSocket 连接、锁定的 RiichiEnv 0.4.11 Observation 夹具及异步 HTTP 模拟传输；未连接真实 `/ws/validate`，未开启排位。B1/B2 仍待实施。

## 交付与退出检查

| 任务 | 实现及验收 |
|---|---|
| B0-1 生命周期 | `online/session.py` 实现 Connecting → Playing → Finishing → Closed；中途断线进入 Disconnected 并标记未完成。`online/client.py` 单次连接，不恢复原局、不自动开启下一局。end_game 后有界等待 validation_result 或正常 WebSocket 关闭；等待到期记录故障，重复 end_game 不延长等待。 |
| B0-2 消息循环 | 独立接收任务与有界消息队列，唯一 owner 顺序更新 tracker、处理 ack 和发送回复。推理仅取得 JSON 快照的独立副本。request_id 先登记再消费 Observation；重复请求不重放、不重复发送。局结束、超时、ack、断线取消推理；即使推理忽略取消，迟到结果也被丢弃。 |
| B0-3 时间预算 | 每请求读取 deadline_ms/grace_ms/bank_ms；接收时记录单调时钟，预算减去入站估计与发送余量，排队和准备快照同样消耗预算。grace 是推理目标，deadline 是回复硬上限，字段不一致时取更紧限制。异步 HTTP 复用连接，启动先预热并验证模型元信息，可直接取消在途请求。 |
| B0-4 备用动作 | 推理失败或超出目标预算时，按合法和牌 → pass → 合法摸切 → 稳定顺序合法弃牌选择。吃碰后无摸牌时选择合法手切。不证明防守安全。不能证明合法或已无发送预算则不发送、等待服务器默认；无合法备用时标记故障。fallback 与 ack 确认的实际执行分别记录。 |
| B0-5 交叉验证 | `online/policy.py` 对完整本地合法集合与 possible_actions 双向校验；区分赤牌、精确 consumed 组合，忽略 consumed 顺序和未知附加字段，尊重给出的 actor/target/tsumogiri 约束。补齐在线动作字段；立直只发送 reach，accepted 后才保留计划，下个独立请求确认状态和候选后发送 dahai。未知信息消息仅记录；未知状态事件或候选冲突停止模型决策并标记故障。 |
| B0-6 密钥 | 平台 token 与 HTTP key 使用不同环境变量，分别只进入 WebSocket Authorization 与 HTTP X-API-Key；拒绝共用变量名。日志递归脱敏两种密钥及敏感字段，不落异常原文中的外部凭据。 |
| B0-7 模拟服务器 | 测试覆盖 turn/response、全部五种 ack、重复 request_id、目标超时、硬期限耗尽、迟到推理、断线、终局等待、两阶段立直、局结束取消、合法备用、状态/候选冲突、密钥与落盘。每个 request_id 至多一条回复。 |

会话保留有条数和字节上限的内存日志，结束连接后写 `session.jsonl` 与 `summary.json`，磁盘写入不阻塞动作回复；容量耗尽使会话失败，写盘失败使命令失败。进程被强制终止时，尚在内存中的日志不保证保留。后续请求若在前一请求 ack 之前到达，按协议次序异常停止；不推测前一动作已执行。

## 复现

```powershell
.venv/Scripts/python.exe -m pytest tests/test_online.py -q
.venv/Scripts/python.exe -m pytest -q
ruff check .
```

验收结果：28 项 B0 测试、141 项全量测试通过，零 skipped；Ruff 检查通过。详见 [机器可读记录](evidence/B0.json)。默认测试无需平台 token、HTTP 服务、训练仓库或网络平台账户。

`arena-online --config configs/arena_online.yaml --output-dir <新目录>` 已接入单次验证客户端，供 B1 使用。配置中的 `RIICHI_DEV_BOT_TOKEN` 与 `TRAIN_MJ_API_KEY` 必须分别设置；无 HTTP 认证时可删除 `api_key_env`。本轮只用本地模拟服务器验收此入口，没有实际运行该平台命令。退出码 0 要求真实返回 passed=true 且会话无故障；fallback/defaulted 仍需 B1 单独审查。

## 验收边界

协议字段依据 [官方协议](https://riichi.dev/docs/protocol) 与 [官方验证流程](https://riichi.dev/docs/validation)（2026-11-03 核对）。本地模拟不代表服务器与锁定发行包的序列化、规则和实际延迟已兼容；真实 validation_result、defaulted/fallback 审查及网络预算实测属于 B1。有界排位与停止阈值属于 B2。

## 当前产物

- Python 3.11.5 / riichienv==0.4.11 / httpx==0.28.1 / websockets==17.4 / PyYAML==6.0.3，uv.lock 固定依赖。
- 60 场种子半庄（1–60）：45,720 个决策、458,100 条合法动作；3,209 个代表 Observation 可重新解码。gzip 游戏文件约 4.93 MB。采集策略修复改变了对局轨迹，因此不沿用旧覆盖计数。
- 完整覆盖索引区分种子命中与定向场景。抢杠/双响夹具是引擎局部设置，不冒充完整半庄；测试实际重建并执行触发动作及和牌。
- full_state_v2 黄金请求来自 seed=1 的真实初始 turn 与首弃牌 response。v1.3.0 真实权重在 CPU 上通过 FastAPI TestClient 的两个预测路由（均 200），selected_action 回查成功；哈希、tag、commit、设备及传输方式保存在 verification.json。
- 网络服务本轮未监听端口；真实路由联调不等于 TCP 或线上验收。probe 的失败/成功语义由 MockTransport 回归覆盖。
- 多后端配置以 v1.2.0 与 v1.3.0 为例，显式登记不同 profile、tag/commit、权重哈希与独立地址。当前只实现静态配置校验；双服务运行属于 A1–A3。

## 重现入口

在本仓库依赖环境：

```powershell
uv run python scripts/capture_fixtures.py --seeds 1-60 --out tests/fixtures/engine
uv run python -m scripts.capture_directed
uv run python -m scripts.capture_http_requests
uv run pytest -q
```

在具备 PyTorch、FastAPI、httpx 的训练开发 Python 环境，以 TRAIN_MJ_ROOT 指向干净 v1.3.0 checkout：

```powershell
python scripts/refresh_http_contract.py --train-mj-root $env:TRAIN_MJ_ROOT
```

该命令只读加载训练代码和权重，通过 TestClient 更新本仓库响应基线，不切换训练分支、不监听端口。重新采集请求后必须重新生成响应，不能保留旧预测结果。

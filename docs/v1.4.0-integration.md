## 契约与适配

新 profile `full_state_v3` 的模型元信息必须是 feature_schema=full_state_v3、状态维度 11969/12012、候选维度 249/251。

HTTP state 仍使用 full_state_v2 公开状态结构；实际模型的 v3 候选编码由服务端根据 checkpoint 选择。适配器额外从 all_discards[actor] 构造独立复制的 own_discards，与训练样本中的自家牌河字段一致。不能把 HTTP state.feature_schema 机械改为 full_state_v3。

首次全量对拍发现，缺少 own_discards 会让 v3 听牌质量中的 discard_furiten 特征在 30 个决策上不一致。补齐后，21 份 XML、14,038 个决策的状态及完整候选特征逐项一致。旧 profile 不受此修正影响。

Response 请求只带 action_biases，不带 pass_bias（包括 null）。服务元信息及每次预测的有效校准均由 HttpPredictBackend 校验。原 Step 1 的 run_v140_screening.py 和 A/B/C 参数仍是旧权重实验，不能用于当前 v3 候选。

## 本地运行

使用已安装项目依赖、torch、FastAPI、uvicorn 和 train_mj 开发依赖的 Python 3.11。在 riichi_lab 根目录执行。以下示例默认两个仓库相邻。

```powershell
$env:TRAIN_MJ_ROOT = (Resolve-Path ../train_mj).Path
python -m rilab.cli parity-check --config configs/parity_v140.yaml --output-dir outputs/v140_parity_new
python scripts/run_a1_integration.py --train-mj-root ../train_mj --config configs/arena_v140_smoke.yaml --seed 40001 --output-dir outputs/v140_smoke_new
```

输出目录必须不存在；启动器自动选择端口、校验权重、归档固定提交源码，退出时回收两个服务。外部 service_config 相对于 riichi_lab 根目录解析，checkpoint 相对于 train_mj 根目录解析。

arena_v140_smoke.yaml 中的 40001 为工程种子；默认命令只运行第一组席位的一场半庄。该配置也包含四席轮换、控制局和 2v2，可使用以下命令重复执行 14 半庄工程日程，不能将其解释为已登记的正式强度实验：

```powershell
python scripts/run_a1_integration.py --train-mj-root ../train_mj --config configs/arena_v140_smoke.yaml --batch --output-dir outputs/v140_engineering_new
```

默认 batch-runs=2，会运行并比较两份各 14 半庄的结果。正式评测的独立种子、预算、协议及资格审计另行接入，不修改原 A4 协议。

## 平台激活与 10 局有界排位

`configs/arena_ranked_v140.yaml` 使用独立的 `RIICHI_DEV_BOT_TOKEN_V140` 平台 token 环境变量、full_state_v3 profile、冻结权重/分动作校准和 10 局预算。手动连接后端时，`backend.api_key_env: TRAIN_MJ_API_KEY_V140` 指定客户端 HTTP key 的环境变量，客户端将其作为 X-API-Key 发送；变量值须与后端服务实际要求的 key 一致，不与平台 token 混用。手动部署默认端口 8014。

自动入口 `run_v140_online.py` 启动专用、无鉴权的本机回环服务，会在运行配置的独立副本中移除 api_key_env，选择空闲端口并保存实际配置，不修改仓库配置。因此自动入口无需设置 TRAIN_MJ_API_KEY_V140；直接使用排位 CLI 连接手动部署的鉴权后端时则必须设置它：

```powershell
$env:TRAIN_MJ_API_KEY_V140 = [System.Net.NetworkCredential]::new('', (Read-Host 'Backend API key' -AsSecureString)).Password
python -m rilab.cli arena-online --mode ranked --config configs/arena_ranked_v140.yaml
```

直接排位 CLI 不启动模型服务，也不执行机器人激活验证。已设置平台 token 且机器人 active、后端服务在对应端口就绪后使用。

```powershell
$env:RIICHI_DEV_BOT_TOKEN_V140 = [System.Net.NetworkCredential]::new('', (Read-Host 'Bot token' -AsSecureString)).Password
python scripts/run_v140_online.py --output-dir outputs/v140_online_new
Remove-Item Env:RIICHI_DEV_BOT_TOKEN_V140
```

入口导出固定提交、核验权重、启动隔离 CPU 服务，先完成一次东风验证并审查协议、fallback/defaulted，全部通过后再执行 10 局半庄排位。`--skip-validation` 仅用于已经确认 active 的机器人，不用于绕过失败的验证。平台 token 不传给模型服务、不写入配置；工具调用还可通过 `--token-stdin` 从私有输入管道传入。

排位沿用现有保守停止阈值：零 fallback、零 defaulted，服务端单次耗时不超过 8 秒，剩余 bank 至少 1 秒，deadline margin 至少 0.5 秒。触发后停止开新局、保留证据，不自动扩大预算或改参。上线结果用于受控平台验证，不替代独立本地强度实验。
